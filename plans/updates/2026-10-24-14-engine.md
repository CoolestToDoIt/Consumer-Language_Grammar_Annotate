# Worker A — correction input integrity

Continuing on `feat/gloss-engine` after bounded-ranking commit `73375d5`.

## Recent work

Reproduced a partial-mutation failure: correcting `('valid', 42)` inserted both
the authoritative record and lexical counts before failing on the integer
token, while version remained zero. Corrections now validate their public
example before touching state: a string ID, immutable nonempty tuple of
nonempty word strings, and aligned gloss labels. A bare string/bytes object
cannot silently become character-level labels. Rule/window bounds must be
positive integers, avoiding later failures during slicing/ranking.

Schema-1 checkpoint loading now rejects malformed record arrays, string fields
where token/gloss arrays are required, and invalid versions (including versions
smaller than the authoritative record count). Valid legacy checkpoints retain
their stored version and continue reconstructing derived state normally.
This is engine-level validation; Worker B still owns session integrity and
experiment resume checks.

58 tests pass. New cases check complete state equality after rejection on fresh
and trained learners, successful correction after an error, malformed bulk
records preserving the valid prefix, constructor validation, and damaged
checkpoint rejection without changing the input file. Full Tsez development
candidates still match the prior artifact in all modes and after reload;
`reports/gloss/performance/tsez-validation-guarded.json` records that check.
