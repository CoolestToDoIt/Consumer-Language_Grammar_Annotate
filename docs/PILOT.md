# Bounded commercial pilot

This edition implements the plan's local workflow assistance offering. Chargeable implementation, training, and support can be arranged separately after scope, data handling, and success criteria are agreed. Pricing, subscriptions, checkout, hosted accounts, and multi-user collaboration are deliberately absent.

Before a customer pilot:

- Confirm upstream software distribution permission and every corpus's permitted uses.
- Interview intended users, choose a representative permissioned sample, and record the current workflow.
- Agree on the annotation conventions, human reviewer, data steward, retention, support scope, and recovery owner.
- Define task completion, annotation effort, corrections accepted, errors caught, import success, and backup recovery measures, with sample sizes.
- Conduct observed trials and compare baseline and assisted workflows. Do not treat training recall or raw candidate scores as held-out accuracy.
- Validate usefulness with more than one target group before setting broad pricing or accuracy/time-saving claims.
- Complete a distribution-appropriate security/privacy review and verify installation, upgrade, export, and restore on intended machines.

Open release gates: external user trials, independent model evaluation on the buyer's language, independent security review, explicit source redistribution terms, buyer-specific governance, and support/pricing agreements. These are external business and validation tasks; the build does not mark them complete.
