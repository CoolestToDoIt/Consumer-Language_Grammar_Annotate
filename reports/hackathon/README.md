## 2. Unseen-word improvement: normalization backoff (opt-in)

Most Tsez "unseen" errors were taught words with attached punctuation
(`ist’owlin,`) or capitalization. `decipher/gloss_backoff.py` only changes
unseen forms: it strips edge punctuation, keeping apostrophe letters such as `ƛ’`,
and casefolds. It then reuses the taught gloss or retries the affix rules.

| Language | Model | Word exact | Unseen-word | Precision when suggesting |
|---|---|---:|---:|---:|
| Lezgi | rules (default) | 72.2% | 15.8% | 84.7% |
| Lezgi | rules + backoff | **73.1%** | **19.8%** | 84.8% |
| Tsez | rules (default) | 75.1% | 35.2% | 83.1% |
| Tsez | rules + backoff | **76.9%** | **44.6%** | 82.7% |

The existing `guess_unknown` fallback reaches similar accuracy but drops
precision to 73–77%. The backoff keeps precision unchanged. The default engine is
unchanged; adopting the backoff by default needs the usual team approval.
See [backoff/dev-comparison.md](backoff/dev-comparison.md).

## 3. User-workflow metrics

Each run simulates the core loop: import unglossed sentences in order, then see
suggestions, accept, pick or type the gloss, and submit. Every suggestion is made
before its sentence is taught. Review triage freezes the fully taught model and
ranks unseen dev words by the review queue's signals.

| Metric | Lezgi | Lezgi + backoff | Tsez | Tsez + backoff |
|---|---:|---:|---:|---:|
| Suggestions accepted as-is | 64.9% | 66.3% | 68.4% | 71.1% |
| Accepted or one-click pick from candidates | 70.7% | 72.3% | 76.4% | 79.2% |
| Gloss characters the user didn't type | 56.8% | 58.5% | 71.4% | 74.1% |
| Precision when a suggestion is shown | 83.8% | 83.6% | 81.8% | 81.7% |
| Teach-once reuse (taught word recurs) | 93.0% | 93.0% | 90.0% | 90.0% |
| Sentences until rolling acceptance ≥ 50% | 103 | 72 | 221 | 201 |
| Sentences until rolling acceptance ≥ 70% | 387 | 221 | 955 | 503 |
| Errors found reviewing top 20% of words (random order ≈ 20%) | 63.0% | 62.2% | 51.7% | 47.9% |
| Unflagged words: share / accuracy | 57.7% / 94.2% | 57.7% / 94.2% | 48.7% / 93.7% | 48.7% / 93.7% |
| Predict latency per sentence (p95) | 0.19 ms | 0.22 ms | 0.22 ms | 0.24 ms |

Readings:
- About 3 in 10 suggestions need typing. When the model makes a suggestion,
  it is right more than 80% of the time.
- One correction reliably teaches a word: about 90–93% of later occurrences
  are right.
- Reviewing the flagged 20% of words catches about 2.4–3x more errors than a
  random 20%. Unflagged words are about 94% correct.
- The backoff cuts the corrections needed to reach 70% acceptance by about
  half on both languages. It slightly lowers review-capture rates, because the
  errors it fixes were easy-to-flag blanks.

Caveats: the simulated user accepts only exact gloss matches, so these are
lower bounds for a lenient human. Rates are empirical on two development
languages, not calibrated probabilities. Acceptance milestones use a rolling
50-sentence window in upstream corpus order, one run per configuration.
